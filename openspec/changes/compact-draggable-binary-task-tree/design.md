## Context

上一轮实现把收起态从嫩芽升级为 224×272 逻辑像素的任务植株，使用五片重叠番薯叶承载标题。用户反馈三个问题：透明窗口没有可发现的拖动入口、整体仍太大、叶簇缺少类似参考图的树状层级。新的形态应当采用参考图中细长、两端收尖的自然叶形，以粗主干逐级二分、同一枝条挂多片叶，并让叶位本身表达排序。

当前任务排序工具以行动等级、异常、稳定顺序和截止时间排序；Tauri 窗口只持久化垂直锚点并根据左右边缘重新定位。若只增加前端拖动手势，窗口在展开或重启时会跳回边缘，因此本变更需要同时调整共享 UI、桌面桥接和原生几何状态。

## Goals / Non-Goals

**Goals:**

- 将收起窗口缩小到 176×216 逻辑像素，并在 100%–200% DPI 下保持完整可点。
- 提供明确的主干拖动把手，让用户可以自由移动悬浮窗且不误触任务。
- 持久化横向和纵向相对锚点，使拖动位置跨收起、展开和重启保持稳定。
- 用原创 SVG 绘制具有粗主干和三层二叉分叉的树形骨架，使用八个参考图式细长尖叶任务位。
- 任务先按重要度降序，再按既有行动排序；高排名任务先占外层叶位，每对兄弟叶位左先右后。

**Non-Goals:**

- 不把任务依赖关系解释为这棵二叉树的父子边；本次树形只表达显示排序。
- 不引入无限递归布局、缩放画布、Neo4j 或 Agent 调度。
- 不在收起态显示完整任务详情、负责人头像或可编辑控件。
- 叶片点击不进入完整 Overlay 工作台；完整面板只通过明确的独立入口打开。
- 不复制参考图片或引入位图资源。

## Decisions

### 1. 使用固定深度二叉骨架和八个叶位

SVG 采用 176×216 viewBox：主干从根部向上延伸，在三个高度形成左右二分；八个任务叶位分成四对兄弟位并沿外枝和内枝分布。枝条是非交互背景，任务仍由独立 HTML button 覆盖在叶位上。

固定骨架能在极小窗口内保持可辨轮廓和可靠命中区域。自动递归树会随任务量改变宽高并重新遮挡桌面，不符合常驻悬浮入口的约束。

### 2. 叶位规则显式建模并可单元测试

每个叶位记录 `pair`、`side`、`outwardRank`、坐标和旋转。槽位数组按 `outwardRank` 升序排列，同一 `pair` 内左位必须位于右位之前。排序后的任务按数组顺序映射，因此“越重要越外”和“左叶高于右叶”不是视觉巧合，而是代码契约。

### 3. 植株排序以重要度为第一关键字

仅常驻植株使用 `importance DESC` 作为第一关键字；重要度相同再复用现有 `stableTaskCompare`，保持行动等级、异常和稳定顺序的确定性。完整任务树的既有行动排序不变。

这直接响应“根据任务重要性排序”，同时避免影响其他视图已经验证过的任务调度语义。

### 4. 使用参考图式细长尖叶作为紧凑任务位

任务按钮使用非对称披针形 SVG：顶部形成向外生长的锐尖，底部收束到枝条连接点，中央叶脉顺着生长方向延伸。叶片按枝条方向旋转，不能画成水平鱼形标签。内部保留序号/状态符号和最多六个汉字的两行摘要；异常继续使用独立描边或小徽标，不依赖颜色。

### 5. 主干透明拖动区域调用原生命令

组件在主干下半段放置透明但可聚焦的拖动按钮，鼠标按下时调用桌面桥接的 `start_overlay_drag`。按钮不绘制图标、底色或常驻提示，仅在键盘聚焦时显示焦点框。任务叶按钮和 `+N` 徽标不属于拖动区域，保持单击语义。浏览器预览中该回调安全为空操作。

选择专用把手而不是让整棵树都可拖动，是为了避免拖动和任务叶点击争夺同一手势。

### 6. 使用双轴归一化锚点持久化位置

原生状态增加可选 `horizontal_anchor`，与已有 `vertical_anchor` 一样表示窗口在当前显示器工作区内的 0–1 相对位置。首次运行仍由左右边缘偏好产生默认横向锚点；拖动后 `on_window_moved` 同时保存双轴锚点，后续尺寸变化按新窗口尺寸重新计算位置并限制在工作区内。

归一化锚点比保存物理像素坐标更能适应 DPI 改变和显示器分辨率变化。

### 7. Preview 模式专门承载轻量任务卡

叶片点击从 `collapsed` 进入 `preview`，而不是进入 `pinned`。Preview 固定为 420×236 逻辑像素，左侧继续显示 176×216 任务树，右侧显示只读速览卡；卡片仅包含判断任务所需的核心字段，不渲染应用导航、列表、编辑表单或任务操作按钮。`pinned` 保留给旧兼容路径，但叶片点击不再使用它。

### 8. 直接关系以树上连线和叶片标记表达

TaskPlantOverlay 接收 `selectedTaskId`，将选中任务与当前八个叶位中的直接前置、直接后续任务映射为 SVG 贝塞尔关系线，并在相关叶上显示“前”或“后”徽标。只绘制数据中真实存在且当前可见的直接关系，不把固定二叉枝条错误解释为依赖边。

## Risks / Trade-offs

- [窗口更小后长标题难以完整显示] → 叶面显示六字摘要，完整标题保留在无障碍名称和点击后的详情中。
- [程序触发的窗口移动也会触发位置保存] → 保存逻辑使用最终工作区和当前窗口尺寸归一化，重复保存是幂等的。
- [展开窗口远大于收起窗口，靠近边缘时中心位置无法完全保持] → 几何函数在工作区内钳制，收起后仍恢复同一归一化锚点。
- [透明拖动区域不易被新用户发现] → 鼠标经过主干时使用抓取光标，键盘聚焦时显示焦点框，但不常驻显示图标或说明。
- [八片叶仍无法容纳全部任务] → 保留 `+N` 溢出按钮并点击进入完整任务树。
- [轻量卡片空间有限] → 只显示核心只读字段，长文本截断；完整编辑留给独立主窗口。

## Migration Plan

1. 增加重要度优先排序和二叉叶位模型，替换植株 SVG/CSS 与组件测试。
2. 增加前端拖动回调和 Tauri `start_overlay_drag` 命令。
3. 增加横向锚点、双轴几何计算和兼容旧状态的反序列化默认值。
4. 更新收起窗口配置与 DPI 测试，完成 Web 视觉和 Windows 原生拖动验收。
5. 将 Preview 缩小为 420×236，加入轻量任务卡、树上关系线并移除可见拖动提示。

旧状态文件缺少 `horizontal_anchor` 时按边缘偏好回退，无需数据迁移。回滚时可忽略新增字段。

## Open Questions

无。本轮先固定八片任务叶和 176×216 逻辑像素，后续根据真实桌面使用反馈再调整密度。
