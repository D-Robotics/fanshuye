## Context

番薯叶桌面端使用一个透明 Tauri overlay 窗口作为常驻入口。当前收起态窗口仅为 74×92 逻辑像素，并通过 React 状态机的进入/离开计时器在 `collapsed` 与 `preview` 之间切换；这种悬停触发会意外遮挡其他窗口。收起态图形也只有装饰性嫩芽，无法让开发团队直接看到当前最值得行动的任务。

本变更同时影响 React overlay 状态机、收起态视觉组件、任务排序复用、Tauri 原生窗口几何和自动化测试。首批用户是开发团队；叶片不显示头像，登录、Agent 自动识别进度和 Neo4j 依赖关系均不在本次范围内。

## Goals / Non-Goals

**Goals:**

- 让悬浮窗的展开完全由明确点击触发，指针进入或离开不再改变窗口状态。
- 用原创 SVG/CSS 绘制一株具有心形阔叶、分层枝干和番薯根块的品牌化植株。
- 在常驻植株上呈现最高行动优先级的任务叶片，并支持从叶片一步打开对应任务。
- 保留键盘、隐私模式、离线只读和 Windows 多 DPI 下的可用性。
- 通过单元测试、组件测试、Rust 几何测试和原生演示运行验证行为。

**Non-Goals:**

- 不接入登录、Agent 进度识别、自动调度或 Neo4j。
- 不修改任务 API、同步协议、数据模型或权限模型。
- 不在叶片上显示负责人头像，也不把完整任务详情塞入收起态。
- 不复刻或打包参考图片；参考图只作为形态与配色灵感。

## Decisions

### 1. 点击直接进入固定展开态

收起植株或任务叶片被点击后，状态机直接进入 `pinned`，而不是先进入会自动消失的 `preview`。`preview` 仍供托盘和全局快捷键的低干扰展示路径使用，但不再由指针事件触发。Escape 和现有关闭控件负责收起。

选择该方案是因为用户点击表达了明确意图，展开窗口需要稳定地接受后续操作。备选方案是点击进入 `preview` 再二次固定，但会增加一次无价值的交互，并保留“窗口为什么自己消失”的困惑。

### 2. 收起植株为代码内 SVG 组件

植株使用一个可测试的 React/SVG 组件实现，包含 SVG 渐变、心形叶片路径、叶脉、枝干和根块；CSS 只负责外部布局、状态动画和焦点样式。任务叶片通过数据映射渲染，装饰层标记为无障碍隐藏。

选择 SVG 是为了在 Windows 多 DPI 下保持清晰、让叶片拥有独立命中区域，并避免新增图片许可和打包依赖。备选的位图贴图无法自然绑定每片任务叶，也会在缩放时变糊。

### 3. 常驻任务采用现有行动排序的前五项

组件复用任务树的确定性行动排序，从未完成任务中选择前五项。优先级更高、已阻塞、逾期和进行中的任务继续沿用现有排序语义；超出的任务以 `+N` 徽标汇总。每个任务叶片使用状态色、异常环和短标题摘要表达信息，但不显示人员头像。

选择固定容量可以控制桌面占用并保持植株轮廓稳定。备选的无限增叶会让窗口尺寸不可预测，也会让命中区域过密。

### 4. 任务叶片点击先选中任务再展开

点击某片任务叶时，应用先更新 `selectedId`，再将 overlay 切为 `pinned`，因此展开后的详情区直接落到对应任务。点击植株背景、枝干或根块只打开总览，不改变当前选择。叶片也支持 Enter/Space。

这样既保留植株作为总入口，又把最高价值任务变成一步直达。事件在叶片内部停止冒泡，避免触发背景点击逻辑两次。

### 5. 扩大原生收起窗口但保持右侧停靠

原生收起窗口调整为约 224×272 逻辑像素，仍按工作区右侧和既有边距停靠。窗口保持透明、无边框、可接收鼠标但不抢键盘焦点；进入 `pinned` 后才成为可聚焦窗口。几何计算继续使用逻辑像素并由已有 DPI 测试覆盖。

该尺寸允许叶片标题和根块在 100%–200% DPI 下仍可识别，同时比完整任务树小得多。备选的 74×92 无法提供足够的可点击任务叶面积。

## Risks / Trade-offs

- [收起窗口比原入口更大，可能覆盖桌面内容] → 保持透明背景、右侧停靠和紧凑轮廓，只有植株本体承载视觉重量，并保留一键收起。
- [五片叶无法显示所有任务] → 使用稳定优先级筛选、`+N` 溢出徽标，并让点击植株进入完整任务树。
- [在 SVG 叶片内显示长标题可能拥挤] → 使用两行短摘要和省略策略，完整标题在展开详情中显示，无障碍名称保留完整文本。
- [旧 hover 测试和预览状态语义冲突] → 删除悬停计时器及相关绑定，新增“指针事件无状态变化”和“点击打开”的回归测试。

## Migration Plan

1. 先替换 overlay 状态机 API 和测试，确保没有悬停入口。
2. 增加任务植株组件并接入 App 的选择/展开流程。
3. 更新 Tauri 收起尺寸及多 DPI 几何断言。
4. 完成 Web 预览、桌面原生构建和演示模式运行验证后提交。

若需回滚，可还原本变更涉及的前端组件、状态机和 `window_geometry` 尺寸；数据与 API 没有迁移，因此无需恢复数据库。
