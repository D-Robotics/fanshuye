## Why

开发团队经常因为任务数量多、责任归属不清、进度状态不可见和多人同时开工而遗忘任务或重复劳动。番薯叶需要先验证一种低打扰的桌面任务态势入口，让团队成员无需反复打开网页即可快速看见当前应做什么、任务是否有人处理以及哪里被阻塞。

## What Changes

- 提供面向开发团队的可安装桌面应用，以系统托盘和屏幕边缘悬浮入口展示共享任务树。
- 一棵树代表一个开发组，叶子代表活跃任务；叶片位置、大小、轮廓和状态标记分别表达行动优先级、重要度、认领情况和工作流状态，叶子不显示负责人头像。
- 提供任务详情与列表视图，支持唯一负责人、多个协作人、截止时间、完成定义、阻塞原因和人工状态更新。
- 提供原子化的任务认领与开始操作，避免两名成员同时独立处理同一任务；提供新建时的活跃任务标题检索以辅助发现重复任务。
- 提供适合开发工作的任务状态流：待处理、进行中、待评审、完成和取消，并将阻塞建模为独立标记。
- 提供人工重要度、派生行动等级和稳定的树布局；支持任务前后依赖、环路拒绝和上下游阻塞判断。
- 提供团队权限、实时同步、版本冲突保护、断网只读缓存、增量恢复和可追溯的任务动态。
- 为未来 Git 集成、Neo4j 图查询投影和 Agent 状态建议预留稳定 ID、领域事件、外部引用和统一命令边界，但首版不实现这些扩展。

## Capabilities

### New Capabilities

- `desktop-task-tree`: 桌面托盘、悬浮入口、任务树速览、固定详情、列表回退和无头像叶片视觉语义。
- `team-task-coordination`: 开发团队工作区、成员权限、任务生命周期、负责人/协作人、认领、防重复开工和阻塞协作。
- `task-prioritization-dependencies`: 人工重要度、派生行动等级、稳定布局以及有向无环任务依赖关系。
- `reliable-task-sync`: 服务端事实源、实时增量同步、并发版本保护、断网只读缓存和连接恢复。
- `task-audit-extensibility`: 任务动态与审计、稳定事件契约、外部引用以及后续 Git、Neo4j 和 Agent 的安全扩展边界。

### Modified Capabilities

无。本项目当前没有既有能力规格。

## Impact

- 新增桌面客户端、模块化单体服务端、共享领域模型和客户端/服务端协议。
- 新增 PostgreSQL 服务端数据存储及桌面端 SQLite 只读缓存。
- 新增账户与团队权限、任务命令 API、WebSocket 增量通知、审计事件和 Windows 桌面集成。
- 首版计划采用 Tauri 2 与 TypeScript UI；仅承诺一个首发桌面平台，其他平台在核心交互验证后评估。
- 首版不包含 Agent、自动进度识别、Git 平台授权、Neo4j、离线写入、复杂项目管理或自定义工作流。
