# 30 任务开发者速览测试

## 当前证据状态

测试装置与机器前置检查已实现，但本文不包含真人测试结果。自动化测试只能证明数据、计时器和判定逻辑可重复，不能证明开发者本人完成了任务。

严格完成 OpenSpec 10.9 还需要一次由观察者见证的开发者测试，并保存本页要求的原始 JSON 与签名记录。

## 固定测试条件

- 数据集：`fanshuye-developer-30-v1`。
- 总任务数：30，其中 26 个活跃任务、4 个历史任务。
- 树面直接显示 15 片叶子，其余 11 个活跃任务进入 `+11` 叶簇。
- 每个测试项独立计时，限时 5,000 ms。
- 四项顺序固定：最高行动等级、无人认领、阻塞任务、Hover 查看负责人。
- 前三项的第一次点击即为答案，不允许在同一轮重试。
- 第四项必须先 Hover 有负责人的叶片，再输入卡片中显示的负责人文字。
- 隐私模式关闭、减少动画开启；不展示任务负责人头像。

## 机器前置检查

在仓库根目录运行：

```powershell
pnpm --filter @fanshuye/desktop test:usability
pnpm --filter @fanshuye/desktop typecheck
pnpm --filter @fanshuye/ui test:run
```

`test:usability` 必须证明：

1. 两次生成的数据完全相同，任务 ID 和标题唯一。
2. 恰有 30 个任务、26 个活跃任务、15 个直显叶片和 11 个聚合任务。
3. `NOW`、无人认领、阻塞和有负责人文字的固定哨兵任务都在直显叶片中。
4. 四项正确操作会记录独立耗时，超过 5,000 ms 会成为 `timeout`，而不是通过。
5. 原始 JSON 始终标记 `OBSERVER_ATTESTATION_REQUIRED`，不会把机器执行伪装成真人结论。

任何一项失败都应停止真人测试，先修复测试装置。

## 启动计时模式

运行：

```powershell
pnpm --filter @fanshuye/desktop study:usability
```

命令会打开：

```text
http://127.0.0.1:1420/?usability=30-task
```

建议使用 1440×900 或更大的显示区域、100% 浏览器缩放和普通鼠标。关闭开发者工具及其他遮挡窗口。不得在正式计时前让参与者浏览测试树。

## 真人测试步骤

1. 观察者确认参与者是目标用户中的开发者，并分配不含真实姓名的代码，例如 `DEV-01`。
2. 观察者只说明：“你将完成四个独立的任务查找，每项点击开始后有 5 秒，第一次点击算最终答案。”不要提前解释问号、阻塞徽标或区域含义。
3. 参与者输入代码，阅读当前提示；准备好后自行点击“开始计时”。
4. “最高行动等级”：参与者点击其认为属于最高行动等级的任意叶片。
5. “无人认领任务”：参与者点击其认为无人认领的任意叶片。
6. “阻塞任务”：参与者点击其认为被阻塞的任意叶片。
7. “Hover 查看负责人”：参与者 Hover 任意有负责人的叶片，读取卡片中的负责人姓名，输入并提交。
8. 测试结束后，观察者复制“原始结果 JSON”，不得手工改写耗时、结果或任务 ID。
9. 观察者按下方模板保存环境和见证信息。若出现误点、超时、外部提示或设备故障，应如实记录；不要重新执行后只保留较好结果。

## 严格通过标准

只有同时满足以下条件，才能把 10.9 视为严格完成：

- 机器前置检查全部通过。
- 参与者身份由观察者确认属于开发者目标用户。
- 四项 `outcome` 全部为 `pass`。
- 四项 `elapsedMs` 均不大于 5,000。
- JSON 中 `datasetId` 为 `fanshuye-developer-30-v1`、`totalTasks` 为 30、`strictPass` 为 `true`。
- 观察者保存未修改的原始 JSON，并完成以下签名记录。

机器自动跑出的通过记录不得替代真人记录。
